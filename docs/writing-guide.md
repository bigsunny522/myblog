# 記事執筆ガイド

CLAUDE.md から分離した執筆ナレッジ。記事を書く時だけ参照する。

## テンプレート

新規記事は `templates/` の雛形をコピーして始める。

- `templates/review-post.mdx`: レビュー記事(製品購入・PR提供品など)
- `templates/news-post.mdx`: ニュース・イベントレポート・まとめ記事

## レビュー記事の標準構成

導入(購入経緯)→ `<BuyLinks>` → スペック(`<Specs>`)+ 特徴(`<FeaturePoint>` ×2〜3)→ 開封・外観(`<ImageGrid>`)→ 使用感 → まとめ(`<ReviewSummary>`: GOOD 3〜5点 / 気になる点 1〜3点)→ 総評。

冒頭に `<CheckList type="good">` で「こんな人におすすめ」を先出しすると、記事の対象読者が早い段階で伝わり離脱率が下がる(任意)。末尾にも `<BuyLinks>` を再掲すると、まとめまで読んだ読者がそのまま購入導線に進める。

## ニュース・レポート記事の構成

導入 → (速報記事なら注意書き)→ キービジュアル(`<ImageModal>`)→ 見出しが多い場合は `<Details summary="目次を開く">` で目次 → トピックごとに見出しを分けて本文 → まとめ・感想。

## 公開前チェックリスト

- [ ] slug が英数字・ハイフンのみ
- [ ] `excerpt` 記入(SNS シェア・SEO 用)
- [ ] `coverImage` 設定 + 画像圧縮済み + WEBP キャッシュコミット済み
- [ ] レビュー記事なら `rating`(+ 可能なら `price` / `faqs`)
- [ ] `date` を **main にマージ(公開)する日付**に更新する(執筆開始日のまま放置しない。日付がズレたまま公開すると再度差し替え・再pushが必要になる)
- [ ] `published: true` に変更
- [ ] `npm run check:posts` が通ることを確認する(フロントマター必須項目・画像参照・WEBPキャッシュ・太字括弧崩れ・タグ/カテゴリの taxonomy 適合を機械チェックする。詳細は `scripts/validate-posts.mjs`)

## 文章表現の注意点

- **太字の範囲を `「」` や `()` などの閉じ括弧で終わらせない**: CommonMark の強調記号の判定ルール上、閉じ側の `**` が閉じ括弧(`」`・`』`・`）`など)に直接隣接し、かつその直後が空白でも句読点でもない通常の文字だと、強調記号として認識されず `*` がそのまま表示されてしまう(例: `**ゲル状（半固体）**に置き換える` → 太字が無効化される)。`「」` だけでなく `()` でも同様に起こるので、太字にしたい語の直後に地の文が続く場合は、括弧を太字の外に出す(例: `**ゲル状**（半固体）に置き換える`)か、括弧ごと太字にせず地の文と区切りを空ける。この崩れは `npm run check:posts` でも検出される
- **`()` による補足説明を多用しない**: 文中に `()` の注釈を挟みすぎると読みにくくなる。本文に直接組み込むか、文を分けて説明する
- **画像の後に手動でスペーサーを入れない**: `<Figure>` や Markdown 画像記法(`![alt](src)`)は下に自動で余白が入るので、`&nbsp;` などの手動スペーサーは不要(入れると余白が二重になる)

## カテゴリ・タグ

`content/data/taxonomy.json` に登録済みのカテゴリ・タグから選ぶ。新しいカテゴリ/タグが必要な場合は、記事を書く前に taxonomy.json に追加する(未登録のまま使うと `npm run check:posts` がエラーになる)。

## コンポーネントの使い方

記事本文で使えるカスタムコンポーネントの一覧・実例は [components.md](components.md) を参照。実装は `components/MDXComponents.tsx`。
